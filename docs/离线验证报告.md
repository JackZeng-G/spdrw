## 2. 每一层证明了什么

**协议层(eeprom)** —— 分页语义(EE1004 SPA / DDR5 MR11)、整片读写、写测试还原、RSWP 位图、
增量写跳过同值、**写入计划把 CRC 排在最后**、失败中止带"已写/未写"计数、干跑只落内存影子:
全部由 Fake 设备驱动, 并在 `-race` 下无数据竞争。
**三级读回退**(块读 32B → 字读 2B → 逐字节 1B)各有独立用例:只禁块读时数据仍正确且落在字读
(事务数 ≈ 字节数/2),块读字读都禁时逐字节读满整片;每级的探测都只读总线、不写。

**写入路径(唯一会变砖的操作)** —— 在全部 67 份真实 dump 上跑**真实写入**(非干跑):
备份 → 按计划逐字节写(CRC 排最后) → 逐字节回读 → 整片校验 → 设备内容与目标逐字节一致。
DDR5 的 NVM 写数**精确等于**变更字节数(保护探测只读 MR);DDR4 及更早因为预检里的写测试
会多出若干次写, 只断言"不少于变更数"。另外三条回滚用例锁住失败路径: 偶发写失败 → 自动回滚
并校验通过;写被静默忽略 → 回读校验失败 → 自动回滚;持续故障 → 回滚失败时给出备份路径。

**总线调优层(smbus tuning)** —— 等待模式(忙等/折中/休眠)常量与校验在可移植文件里,
Linux 下就测:`TunerOf` 必须能透过计数/记录/双层包装找到硬件会话的调优能力, 而**不能**
把一个没有该能力的 Fake 误报成"可调优"(`TestTunerOfUnwrapsWrappers`);服务层在不可调优
与未连接时都要报可读错误(`TestBusTuningUnsupportedOnFake`)。

**校验区表(CRCRanges)** —— 与校验器 CRCOK 逐字节对齐:67 份真实 dump 的 **35584 个偏移**各翻 2 个
bit,"参与校验的字节翻转后必失败、不在范围内的字节翻转后必须仍通过"全部成立(仅跳过决定世代的字节)。
另按 JEDEC 布局断言:DDR4/DDR5 的身份区(序列号/生产日期/部件号)不在校验范围内,DDR3 的序列号在、
部件号不在 —— 这正是"改序列号却提示重算 CRC"那个问题的判定依据。

**解析层(spd)** —— 67 份真实 dump 全部识别正确、CRC 全部通过; DDR4 JEDEC/ XMP 2.0、
DDR5 JEDEC/XMP 3.0/EXPO 的字段用**厂商型号里公开的规格**做外部参照核对
(Corsair 5600 CL40 1.25V、GeIL 8000 CL38 1.45V、G.Skill EXPO 6000 1.35V、
Viper4 3200 的 tRAS/tRC 36/64 周期…)。

**编辑层(editor)** —— 与解析层是两套独立实现, 交叉校验要求两边对同一根条给出同一个值;
每个字段"改一次再改回"必须逐字节复原(唯一例外是时序的等价编码, 按时间等价判定);
字段写入不得越界到 CRC 字节或相邻字段。

**服务层与界面(app/frontend)** —— 绑定契约(≤2 返回值、参数形态)、写入预检与确认串、
备份、干跑、总线事务计数、编辑器标签页、写保护面板: Node 契约测试 + **真实浏览器**跑真实
发布页面(`make-real-page.mjs` 从 `dist/index.html` 生成, 不是骨架副本)。

**产物** —— exe 内嵌前端与 PawnIO 模块的静态自检通过。

## 3. 审查发现的问题(已全部修复)

先后请两个"新鲜上下文"的子代理做独立正确性审查。第一轮找出 10 个问题, 其中两条高严重度:

1. **XMP 2.0 的 tRAS/tRC 高位 nibble 位序错了**(沿用了原版 C# 的错误, 且 tRC 丢了高位)——
   改一次 tRAS 会把真实 tRC 从 40ns 清成 8ns, 而 XMP 区不在 CRC 覆盖内, 校验照样通过。
   我用自己的独立计算 + 厂商规格确认了审查是对的(按旧位序是 87/103 周期, 按 JEDEC 是 36/64、39/64)。
2. **干跑/预检的写保护探测真的写总线**(DDR4/更早靠"取反写一字节再还原"), 而"零 NVM 写"
   统计窗口却从预检之后才开始 —— 既真写了又报告"零写入"。

其余: 并发(共享 Editor map 与 Device 分页状态无保护)、XMP2 CL 越界写入、XMP2 tRFC 单位错 8 倍、
空 XMP3 槽不补 CRC、`EditVerifyFile` 越界 panic、"幽灵变更"、DDR3 FTB 整数除法、两处
`CRCOffsets` 判定漂移。修复过程中我自己还犯过一次锁嵌套(自锁死), 靠 `-race` 跑到超时才发现,
现已加机械守卫。详见 `docs/实现文档.md` 的"独立审查发现并修掉的问题"一节。

### 第三轮: 写入路径对抗性审计(2026-09-21, 真机写入前)

请第三个子代理**只针对"会不会把条写坏"**做对抗性审查(读代码 + 用 Go overlay 注入故障复现)。
它找出 **1 个阻断项 + 2 个高危 + 5 个中危 + 6 个低危**, 全部已修并有用例钉住:

| 级别 | 问题 | 修法 |
|---|---|---|
| **阻断** | **备份晚于写保护探测**: DDR4/更早的探测本身是真实 NVM 写(块首取反写→还原)。还原写一失败, byte0 被永久改坏, 而备份里存的也是坏值, 回滚拿坏值比对自己还报"无需回滚" | 备份提到**任何探测之前**;探测后整片复核, 不一致立即回滚并**中止**写入(`TestBackupHappensBeforeProbeWrite`) |
| 高 | **世代不对照**: 只比长度与 dump 自身 CRC。256B 的 DDR3 镜像能写进 DDR2 条(反之亦然) | 预检与写入两道门都比对 `spd.Identify(dump)` 与设备类型, 不一致/类型未知一律阻断(`TestGateDumpRejectsCrossGeneration`) |
| 高 | **"查询保护状态"是无备份无确认串的真实写**; RSWP 加/清除只看 quick 是否 ACK | 查询前先备份 + 探测后复核; WPSet/WPClear 要确认串(`RSWP`/`CLEAR`)并**回读复核**是否真的生效(`TestWPSetClear`) |
| 中 | `writeWithPreflight` 只信调用方传来的预检; `WriteConfirmed` 读两次文件(TOCTOU) | 只读一次并一路复用; 内部独立复检长度/世代/CRC(`TestWriteWithPreflightGatesDataItself`) |
| 中 | **预览会写设备**: 干跑影子建立失败时错误被吞, 照跑 DDR4 写测试(实测 8 次数据写) | 建影子失败即中止预览, 不探测(`TestPreviewNeverWritesEvenWhenShadowFails`) |
| 中 | "NVM 写"从有上限(512)的写日志里数, force 写 1024 字节会少报一半 | 传输层独立累计(`TestNVMWriteCountNotTruncated`) |
| 中 | BIOS "SPD Write Disable" 读了但从不参与门禁 | 预检直接按 `bios` 阻断, 干跑放行但带警示(`TestBIOSWriteDisableBlocksRealWrite`) |
| 低 | MR11 整字节写会清 bit3(寻址模式位); 备份名秒级精度同秒互相覆盖; 逐字节回读与整片校验共用同一条读路径; 回读阶段"已写"少算 1; 空计划也写备份 | 全部修正(读-改-写 MR11 并保留高位; 备份名加纳秒; 改动字节再用**逐字节**读法复核; 计数修正; 空计划直接返回) |

审计同时判定 5 个类别**干净**并给了证据: CRC 最后写、写后校验、分页语义、
干跑(除上述预览缺陷)、并发(opMu 覆盖), 以及 force/增量模式与确认串。

## 4. 这套离线验证**没有**覆盖什么(必须真机确认)

| 未覆盖 | 为什么只能真机 | 对应验证步骤 |
|---|---|---|
| 真实 SMBus 时序/仲裁 | Fake 不模拟总线电气与控制器重试; Thaiphoon/OpenRGB 同时占用时的表现 | V1 |
| 真实颗粒的写周期与保护行为 | `eepromWriteDelay(25ms)`、NACK/超时处理、RSWP 探测在实物上的表现 | V3/V5 |
| BIOS 是否接受修改后的 SPD | 容量/时序/扩展区的解释权在固件 | V4 |
| 干跑在真机上确实零写入 | 离线只能证明代码路径; 真机用**总线计数**读出来才算证据 | **V2** |
| Windows/WebView2 运行时 | 容器内只有 Chromium + DOM 桩, 不是 Wails 的真实运行时 | V1 起 |
| DDR2 | 公开渠道**没有任何**真实 dump(已穷举 coreboot 全量 `.spd.hex` + 多轮仓库搜索), 只有合成样本覆盖 | 遇到 DDR2 先只读 |
| 字读(2B/事务)在本机 HUB 上的表现 | 探测靠"字读结果 == 两次字节读结果"比对, 只读且失败即降级, 但**是否被接受只有真机能答** | V1 看日志档位 |
