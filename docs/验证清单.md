# 真机验证清单

在真实硬件上部署前逐项确认。所有"读取"类操作无风险;"写入/保护"类操作请先读懂每一步。

## 0. 环境

- [ ] Windows 10/11 x64, 已安装 [PawnIO](https://pawnio.eu/) 最新版
- [ ] 以管理员身份运行 `SPDReaderWriter.exe`
- [ ] 主界面右上角显示 "就绪 · N 个控制器", 无黄色警告条
- [ ] (可选) BIOS 中 "SPD Write Disable" 关闭(写入前必须)

## 1. 控制器枚举(只读)

- [ ] Intel 平台: 出现 "Intel PCH SMBus (I801)" 且显示 PCI 地址
- [ ] AMD 平台: 出现 KernCZ PIIX4 (可能 2 个端口条目)
- [ ] 服务器 Skylake-SP: 出现 "Skylake IMC SMBus" ×2
- [ ] 与 CPU-Z / HWiNFO 的 SMBus 控制器 PCI ID 一致

## 2. 扫描与读取(只读)

- [ ] 每根内存条出现在 0x50-0x57, 数量与插槽数一致
- [ ] 类型识别正确(DDR4 显示 DDR4, DDR5 显示 DDR5)
- [ ] "读取" 得到 512B(DDR4)/1024B(DDR5), 十六进制视图按高 nibble 着色
- [ ] 日志写明读取方式与事务数: 形如
      `读取 1024 字节: 块读(32 字节/事务); 事务 33 次, 耗时 1.0s(等待 0 ms)`,
      或字读档 `… 字读(2 字节/事务); 事务 520 次, 耗时 16s …`, 或
      `… 逐字节(1 字节/事务); 事务 1024 次, 耗时 32s …`(最后一种还会带"回退原因: …")。
      **把这一行回帖**即可对比提速效果(读路径按 块读 32B → 字读 2B → 逐字节 1B 自动降级)
- [ ] (可选)取消勾选"读加速"再读一次, 对比耗时; 若加速档数据与逐字节不一致, 请把两条日志都回帖
- [ ] 信息面板: 厂商/部件号/序列号/生产日期与 CPU-Z、Thaiphoon 一致
- [ ] 容量与实际一致(例: 2×16GB 双列显示 16 GiB)
- [ ] DDR4: CRC 校验通过(若失败, dump 可能分页错位 — 重读一次)
- [ ] DDR4 时序: tCL/tAA/tRCD/tRP/tRAS 与 BIOS/CPU-Z 一致
- [ ] XMP 条目: 频率-时序-电压与包装标签一致
- [ ] DDR5: CRC(基础段)通过; XMP/EXPO 存在性正确
- [ ] (对照) DDR2/DDR3 老平台: 容量与部件号正确

## 3. 写保护状态(只读; DDR4 及更早无状态寄存器, 查询会对块首做"写测试"= 写入取反值再还原)

- [ ] "查询保护状态"返回块列表并显示字节范围: DDR5 = 16 块 × 64B, DDR4 = 4 块 × 128B, DDR3 = 1 块 × 128B
- [ ] 出厂未保护的条: 全部 🔓; 已 RSWP 的块显示 🔒(可先用别条测试)
- [ ] DDR5: MR12/MR13 原始值与 Thaiphoon/参考工具一致; `MR52[6]=1` 表示"最近有写受保护块被忽略"
- [ ] DDR5: **不再出现**"PSWP 永久保护已生效"—— 该世代无 0110b(PWPB)设备类型, 面板应显示"PSWP 不适用"
- [ ] DDR2/DDR3: PSWP 未设置/已永久保护 与实机一致(永久保护后器件不再应答 0x30|SA)
- [ ] DDR4 等: 若某块写测试失败, 该块显示 ❔ 未知(而不是谎报受保护), 日志给出"还原失败 + 偏移 + 原值"警告
- [ ] 查询后重新 dump, 内容与查询前逐字节一致(写测试确实还原了)

## 4. 写入(有风险 — **必须按顺序, 严禁跳步**)

每一阶段都要求: 已保存原始 dump + 另存一份冗余备份; 目标 dump 的 CRC 校验通过。

### V0 离线(容器内, 无硬件)
- [ ] `go test ./internal/...` 全绿(84 个用例, 约 3 秒)
- [ ] `CGO_ENABLED=1 go test -race ./internal/...` 全绿(并发与死锁守卫)
- [ ] `node --test "frontend/test/*.test.mjs"` 全绿(20 条: 页面漂移守卫 + 绑定契约)
- [ ] 真实发布页面在浏览器里跑 `frontend/test/_real-page.html`, 读 `window.__SMOKE`
      (29 步全 ok、`window.__ERRORS` 为空)
- [ ] 产物自检: `go test ./internal/app/ -run TestBuiltExeEmbedsAssets`(前端与 PawnIO 模块确实打进了 exe)

### V1 只读基线
- [ ] 读取 → 保存 dump → 解析 → CRC 通过
- [ ] "查询保护状态" 与上节一致

### V2 干跑(dry-run, 零风险)
- [ ] 勾选"干跑模式", 选一份修改过的 dump → 输入 `DRYRUN`
- [ ] 预检面板显示: 变更字节数、CRC 字节数、区域/风险表、逐字节 diff
- [ ] 执行后日志显示"将写入 N 字节; 期间总线事务: 读 X / 页选择与命令写 Y / 字节写 Z,
      其中对 SPD NVM 的数据写 0 次(零写入)" —— **把这行日志原样回帖**即 V2 的证据
- [ ] 重新读取设备内容**未变**
- [ ] (可选) 界面上干跑前后各点一次"总线统计", 确认差值与上面日志一致
- [ ] 换一根**开了 RSWP** 的条再干跑一次: 应照样给出计划(消息里带写保护提示),
      但把"干跑"取消后点写入 → 必须被拒绝并说明受保护块号
- [ ] 用一份 CRC 不通过的文件 → 干跑也必须被拒绝(数据本身不合格)

### V3 牺牲条: 单字节
- [ ] 用可牺牲的内存条; 只改序列号(或厂商)1 个字节并保持 CRC 有效
- [ ] 写入前: 自动备份路径出现在日志中
- [ ] 输入 `WRITE` 后写入 → 日志"写入并校验通过"
- [ ] 重新读取: 目标字节已变、其余字节不变、CRC 通过
- [ ] 用备份写回并确认复原

### V4 牺牲条: 扩展区(XMP/EXPO)
- [ ] 修改/新增 XMP 或 EXPO 后写入
- [ ] BIOS/系统里确认 profile 被识别
- [ ] 写入一份 CRC 故意不通过的文件 → 预检必须阻断(不写任何字节)

### V5 RSWP(可选, 不可逆性因条而异)
- [ ] RSWP 设置单块 → 状态显示该块 🔒; 重上电后仍保护
- [ ] RSWP 清除 → DDR4 走 CWP quick 命令; DDR5 写 MR12/MR13=0(可能需要离线模式/断电)

### 异常路径(任选一条牺牲条验证)
- [ ] 未装 PawnIO / 非管理员: 黄条提示, 不崩溃
- [ ] 写入过程中拔条或制造 NACK: 错误信息给出"已写 N 字节 / 未写 M 字节 + 恢复建议", 不静默半写
- [ ] 文件长度与 SPD 大小不一致: 预检直接阻断(不再有切片越界)

## 已知边界

- PSWP(永久写保护)只有 DDR2/DDR3 能用 SMBus 探测; 设置需高压(HV)编程器, 本工具不做
- DDR5 的 MR12/MR13 位在正常运行时不可清零: 解除需离线模式(MR48 bit2)或断电, 由主板/平台决定
- DDR5 时序字段在旧版未解析(本版已补), 笔记本/紧凑机型 SPD 可能挂在专用控制器上
- 部分 AM5/ITX 板 SMBus 由桥接芯片转发, PIIX4 端口可能需要两个都试
