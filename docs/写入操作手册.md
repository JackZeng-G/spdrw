# 写入操作手册(真机)

写入是**唯一可能让内存条变砖**的操作。这份手册是照做就能安全完成的顺序, 不要跳步。
所有"擦除/保护"类设置(RSWP/PSWP)都属于不可逆操作, 不在本手册的第一步里。

---

## 0. 写入路径会为你做的事(先知道护栏在哪)

| # | 护栏 | 在哪一步 |
|---|---|---|
| 1 | 文件长度必须与设备 SPD 大小**完全一致**(不截断、不补齐) | 预检 |
| 2 | **世代必须一致**: 目标内容的世代(byte2)与设备识别出的世代比对; 长度相同也不许跨世代 | 预检 |
| 3 | 目标 dump 自身 **CRC 必须有效**(写入一份坏 SPD = 让主板按错时序启动) | 预检 |
| 4 | 设备当前内容 CRC 不通过会**警告**(说明之前被半写过) | 预检 |
| 5 | **BIOS 的 SPD Write Disable** 打开时直接拒绝(别走到失败回滚才发现) | 预检 |
| 6 | 写保护探测: DDR5 读 MR12/MR13 位图; DDR4 及更早对块首做"取反写→还原"写测试 | 预检 |
| 7 | 变更涉及**受写保护的块** → 直接拒绝(附块号) | 预检 |
| 8 | 生成逐字节计划: 增量模式只写不同的字节, 高危字节(容量/电压/PMIC)单独计数 | 预检 |
| 9 | **写入前自动备份**——而且排在**任何探测之前**(探测本身就是写, 见下) | 探测/写入之前 |
| 10 | 探测之后**整片复核**:内容与备份不一致(还原写失败) → 自动回滚并**中止**本次写入 | 探测之后 |
| 11 | **CRC/校验字节排在计划最后写**:中途失败不会留下"内容变了但校验还被认为有效"的 SPD | 写入 |
| 12 | 每个字节**写完立即回读**, 之后整片校验, 最后对**改动字节**再用逐字节读法复核一遍 | 写入中/后 |
| 13 | 任何失败(写 NACK/超时/回读不符/整片校验不符)→ **自动用写入前镜像回滚**并再校验 | 失败时 |

> **为什么备份必须排在探测之前**: DDR4 及更早世代没有保护状态寄存器, 判断"这块能不能写"
> 只能对块首**取反写一个字节再还原**——探测本身就是一次真实 NVM 写。byte0 是 SPD 字节数/修订,
> 位于基础 CRC 覆盖区内:还原写一旦失败, 该条立刻 CRC 失效、主板拒用。所以备份必须最先做,
> 探测后还要复核, 不一致就回滚+中止。**DDR5(DDR5 hub 读 MR12/MR13)没有这个风险。**

确认串:真实写入必须输入 `WRITE`,干跑必须输入 `DRYRUN`(大小写不限)。

## 1. V2 干跑(零风险, **必须先做**)

目的:证明"这套流程在真机上跑得通, 而且真的一个字节都没写"。

1. 管理员运行 `SPDReaderWriter.exe` → 枚举控制器 → 扫描 → 选目标条 → **读取**。
2. 切到 **编辑器** → **从设备载入**。
3. 改一个无关紧要的字段(例如序列号最后一个字节), 点 **重算 CRC**(改的是校验范围内的字节时才需要)。
4. 勾 **干跑(不写入)** → 确认串输入 `DRYRUN` → **预览并写入设备…**。
5. 看日志, 期望出现:

```
干跑完成: 将写入 N 字节; 期间总线事务: 读 X 次 / 页选择与命令写 Y 次 / 字节写 Z 次, 其中对 SPD NVM 的数据写 0 次(零写入)
```

**把这一行原样回帖**——`对 SPD NVM 的数据写 0 次` 是"干跑确实没写盘"的唯一硬证据。
界面"总线统计"里的 **NVM 写** 也必须同时是 0。

6. 再点一次 **读取**, 内容应与干跑前逐字节一致。

> 若干跑里出现 NVM 写 > 0 —— **立刻停止, 不要做真实写入**, 把日志发我。

## 2. V3 第一次真实写入(牺牲条, 改**不影响校验**的字节)

第一次只写**数据字节、不带 CRC**, 把"写入 + 回读校验"这条链路单独验一遍。
DDR4/DDR5 的 **序列号(0x145-0x148 / 0x205-0x208)** 正好在 CRC 覆盖范围之外, 是最合适的目标。

> **目标选择**:两根条都在机上时, 优先写**你能舍弃的那一根**(例如 0x51 那根)。
> 万一它变得 POST 不认, 拔掉它用另一根仍能开机。只改序列号时 SPD 依然完全有效,
> 正常情况下开机不受影响——但把"最坏情况的退路"先想好。

1. 确认已有一份原始 dump 存在别的机器/网盘(程序也会自动备份一份)。
2. 编辑器 → **从设备载入** → 改 **序列号(hex)** 为已知值, 例如 `DEADBEEF` → **应用**。
   左侧 hex 里这几格应显示**蓝底蓝框**(不在校验范围), 校验状态仍是 `CRC 通过 · N 处改动不在校验范围`。
3. **不要**勾干跑 → 确认串输入 `WRITE` → **预览并写入设备…**。
4. 期望日志:

```
写入并校验通过: 4 字节(备份 /root/.spdrw/backups/spd-0x50-....bin); 总线: 读 X / 字节写 Y(其中 NVM 4)
```

5. 立刻 **读取** 一次, 确认:
   - [ ] 序列号变成 `DEADBEEF`, 其他字段与写入前一致
   - [ ] CRC 仍然通过(序列号不在校验范围内, 所以不需要重算)
   - [ ] "总线统计"里 NVM 写 = 4(与计划字节数一致)

做完这一步, 写入链路(备份→按字节写→逐字节回读→整片校验)就在真机上验证过了。

---

## 3. V4 写入**校验范围内**的字节(可选, 更接近真实用途)

1. 编辑器 → **从设备载入** → 改一个 JEDEC 时序字段(例如 tCK 或 tAA)→ **应用**。
2. 左侧对应格子应显示**红底红框**, 校验状态变 `CRC 需重算`。
3. 点 **重算 CRC** → 状态回到 `CRC 通过 · N 处改动已计入校验`。
4. 确认串 `WRITE` → 写入 → 读回确认时序与 CRC(计划里 CRC 字节应排在最后, 可在写入前预览面板的逐字节 diff 里看到)。

## 4. 出问题怎么办(按现象查)

| 现象 | 含义 | 处理 |
|---|---|---|
| `写入被拒绝: 变更涉及受写保护的块 [2]` | 该块 RSWP 打开, 硬件不接收写入 | 先看"查询保护状态";RSWP 只能清除(部分平台需离线模式/断电), 不可逆 |
| `写入被拒绝: 该条已处于 PSWP 永久写保护` | 永久保护(DDR2/DDR3) | SMBus 无法写入, 需高压编程器 |
| `写入中止(write)@ 0x2C5: 已写 3/4 字节, 未写 1 字节 …` | 写 NACK/超时, 中途停住 | 看同一行的回滚结果 |
| `…; 已自动回滚到写入前内容(N 字节, 读回校验通过); 备份 …` | **已恢复原状** | 无需操作;排查原因(BIOS 写保护、其他工具占用 SMBus)后重试 |
| `…; 自动回滚失败: …; 请立刻用备份 … 重新写入该条 SPD` | 硬件持续拒绝写入, 内容可能不完整 | 用该备份文件走"打开文件解析 → 写入文件… → `WRITE`";仍失败则考虑离线编程器 |
| 写入"成功"但重读内容和目标不一致 | 不可能:写入内有逐字节回读 + 整片校验 | 若真出现, 保留日志与工具版本号发我 |
| BIOS 里 SPD Write Disable 打开 | 所有写事务被 BIOS 拦截 | BIOS 关闭该项后再写 |

### RSWP 加保护 / 清除(不可逆, 单独记)

- 两个动作都要**确认串**: 加保护输入 `RSWP`, 清除输入 `CLEAR`(在"写保护"面板的确认串框里)。
- 下发后程序会**回读复核**是否真的生效: DDR5 读 MR12/MR13 位图; DDR4 及更早用写测试复核。
- EE1004 的 SWP/CWP 命令需要 WP 引脚上的 VHV, 器件可能"ACK 但忽略" —— 所以"命令没报错"
  不算成功, 回读对不上会明确报错。加保护在部分颗粒上**不可逆**(清零要离线模式或断电)。

**离线恢复路径**(主板已经认不出该条时):换到能用编程器/另一台机器的环境, 把 `~/.spdrw/backups/` 里的原始镜像写回;本工具也支持"打开文件解析… → 写入文件…"对同一地址重写。

## 5. 每次写入前 30 秒自检

- [ ] 只改**一根**条, 且已有一份原始 dump 在别处(网盘/U 盘)
- [ ] 目标 dump 的 CRC 通过(编辑器里能看到)
- [ ] 已经跑过一次**干跑**并看到"零写入"
- [ ] 知道这次的备份路径(`~/.spdrw/backups/spd-0xNN-<时间>.bin`)
- [ ] 机器没有别的工具在占用 SMBus(Thaiphoon/HWiNFO/OpenRGB 关掉)
- [ ] 已读第 4 节的失败处理

## 6. 常见问题

**Q: 写入要多久?**
每个字节一次事务 + 写周期(约 25ms), 再加回读;改 4 个字节通常在 1 秒内。改上百字节要几十秒, 期间不要切换设备/关程序。

**Q: 能不能改容量、频率这些"大字段"?**
能, 但它们属于**高危字节**(预检会单独计数并要求你确认)。写入一份与颗粒不匹配的 SPD 可能让主板拒绝该条甚至无法开机——除非你清楚后果并在牺牲条上做。

**Q: 干跑和真实写入的差别?**
干跑把写落到内存影子, 总线零写事务;真实写入在干跑同样的计划之上真正下发写事务, 并且多了"备份 → 逐字节回读 → 整片校验 → 失败自动回滚"。
