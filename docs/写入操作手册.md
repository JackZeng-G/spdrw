# 写入操作手册(真机)

写入是**唯一可能让内存条变砖**的操作。这份手册是照做就能安全完成的顺序, 不要跳步。
所有"擦除/保护"类设置(RSWP/PSWP)都属于不可逆操作, 不在本手册的第一步里。

---

## 0. 写入路径会为你做的事(先知道护栏在哪)

| # | 护栏 | 在哪一步 |
|---|---|---|
| 1 | 文件长度必须与设备 SPD 大小**完全一致**(不截断、不补齐) | 预检 |
| 2 | **世代必须一致**: 目标内容的世代(byte2)与设备识别出的世代比对; 长度相同也不许跨世代 | 预检 |
| 3 | 目标 dump 自身 **CRC 必须有效**(写入一份坏 SPD = 让主板按错时序启动) | 预检 |
| 4 | 设备当前内容 CRC 不通过会**警告**(说明之前被半写过) | 预检 |
| 5 | **BIOS 的 SPD Write Disable** 打开时直接拒绝(别走到失败回滚才发现) | 预检 |
| 6 | 写保护探测: DDR5 读 MR12/MR13 位图; DDR4 及更早对块首做"取反写→还原"写测试 | 预检 |
| 7 | 变更涉及**受写保护的块** → 直接拒绝(附块号) | 预检 |
| 8 | 生成逐字节计划: 增量模式只写不同的字节, 高危字节(容量/电压/PMIC)单独计数 | 预检 |
| 9 | **写入前自动备份**——而且排在**任何探测之前**(探测本身就是写, 见下) | 探测/写入之前 |
| 10 | 探测之后**整片复核**:内容与备份不一致(还原写失败) → 自动回滚并**中止**本次写入 | 探测之后 |
| 11 | **写入档位自适应**: 逐字节写(协议 2)为先; 若回读发现没写进去, 自动改试**块写(协议 5)**, 成功就切档继续并写进日志 | 写入中 |
| 12 | **CRC/校验字节排在计划最后写**:中途失败不会留下"内容变了但校验还被认为有效"的 SPD | 写入 |
| 13 | 每个字节**写完立即回读**(固定用最原始的逐字节读, 避免读路径缓存骗人)→ 整片比对 → 再关掉块读/字读**整片逐字节复核** | 写入中/后 |
| 14 | 任何失败(写 NACK/超时/回读不符/整片校验不符)→ **自动用写入前镜像回滚**并再校验 | 失败时 |

> **为什么备份必须排在探测之前**: DDR4 及更早世代没有保护状态寄存器, 判断"这块能不能写"
> 只能对块首**取反写一个字节再还原**——探测本身就是一次真实 NVM 写。byte0 是 SPD 字节数/修订,
> 位于基础 CRC 覆盖区内:还原写一旦失败, 该条立刻 CRC 失效、主板拒用。所以备份必须最先做,
> 探测后还要复核, 不一致就回滚+中止。**DDR5(DDR5 hub 读 MR12/MR13)没有这个风险。**

确认串:真实写入必须输入 `WRITE`(大小写不限)。界面已不再提供"干跑"与"我已另有备份"两个勾选:
备份每次都自动做, 预检面板承担写入前的预览。

## 0.5 能不能"只写一个很小的字段"?(能, 这就是推荐做法)

**默认是增量写入**: 只有"与设备当前内容**不同**的字节"会下到总线, 其余字节连一个写事务都不发。

- 改 **1 个字节** → 总线上下发 **1 次** NVM 写(写入结果里 `NVM 4` 这种数字就是它)
- 勾了**强制模式**才会写全部(512/1024 字节)—— 那是修复用的, 别勾
- 编辑器路径**固定** `force=false`, 没有地方能误勾

所以拿"不重要的位置"做第一次写入测试完全可行, 推荐顺序:

| 目标 | 计划字节数 | 说明 |
|---|---|---|
| 序列号的**某一个字节**(如 0x208) | **1**(无 CRC 字节) | 最安全: 不在任何 CRC 覆盖范围内, 写完 SPD 依然完全有效 |
| 整个序列号 4 字节 | 4 | 同上, 只是多改几个字节 |
| JEDEC 时序字段(如 tCK) | 3(数据 1 + CRC 2) | 会连带改 CRC, 属于"写入校验区内"的测试 |
| DDR3 的序列号 | 5(数据 4 + CRC 1... 视长度) | DDR3 的序列号**在** CRC 覆盖范围内 |

预检面板会写清: `本次**只会**写上面这 N 个字节: 其余 XXX 个字节不发送任何写事务`。

## 1. 预检面板(零风险预览; 原"干跑"已从界面移除)

> **说明**: 界面上的"干跑"勾选已经去掉 —— 写入链路在真机上验证通过后, 它的日常价值只剩"零写入预演",
> 而**预检面板**已经承担了这部分(它算计划/diff/风险/CRC, 只在真正写入那一刻才下发数据写;
> 需要严格的"零写入"证据时, 可在测试里走后端 `dryRun` 参数)。

目的:先看清这次会写哪几个字节、有没有风险, 再决定要不要写。

1. 双击 `SPDReaderWriter.exe`(清单要求管理员, 会弹 UAC, 同意后启动) → 枚举控制器 → 扫描 → 选目标条 → **读取**。
2. 读取后编辑器会**自动载入**刚读到的内容(界面已无"从设备载入"按钮)。
   要改文件里的 dump: 顶栏右侧 **打开 dump 文件…**(载入后 SPD 信息与 hex 也会同步显示)。
3. 改一个无关紧要的字段(例如序列号最后一个字节; 改的是校验范围内的字节时要先点"重算 CRC")。
4. 点 **写入设备…** → 看预检内容:
   - `变更 N 字节(其中 CRC M 字节, 按计划最后写入)`
   - `本次**只会**写上面这 N 个字节: 其余 XXX 个字节不发送任何写事务`
   - `写入后自动校验: ① 每个字节写完立即回读 ② 整片比对 ③ 整片逐字节复核(关掉块读/字读)`
   - 世代对照、CRC 是否通过、写保护与 BIOS 写禁止有没有拦人
5. 预检没问题 → 确认串 `WRITE` → 执行。

## 2. V3 第一次真实写入(牺牲条, 改**不影响校验**的字节)

第一次只写**数据字节、不带 CRC**, 把"写入 + 回读校验"这条链路单独验一遍。
DDR4/DDR5 的 **序列号(0x145-0x148 / 0x205-0x208)** 正好在 CRC 覆盖范围之外, 是最合适的目标。

> **目标选择**:两根条都在机上时, 优先写**你能舍弃的那一根**(例如 0x51 那根)。
> 万一它变得 POST 不认, 拔掉它用另一根仍能开机。只改序列号时 SPD 依然完全有效,
> 正常情况下开机不受影响——但把"最坏情况的退路"先想好。

1. 确认已有一份原始 dump 存在别的机器/网盘(程序也会自动备份一份)。
2. 编辑器里改 **序列号(hex)** 为已知值, 例如 `DEADBEEF` → **应用**。
   (界面上不再需要勾"我已另有备份": **每次写入前程序都会自动整片备份**, 备份路径会打进日志。)
   左侧 hex 里这几格应显示**蓝底蓝框**(不在校验范围), 校验状态仍是 `CRC 通过 · N 处改动不在校验范围`。
3. 确认串输入 `WRITE` → **写入设备…**。
4. 期望日志:

```
写入并校验通过: 4 字节(备份 /root/.spdrw/backups/spd-0x50-....bin); 总线: 读 X / 字节写 Y(其中 NVM 4)
```

5. 写完后程序会**自动**重新读取设备做独立复核(不需要手点), 日志出现
   `自动复核通过: 设备内容与写入内容逐字节一致`。也可以自己再 **读取** 一次确认:
   - [ ] 序列号变成 `DEADBEEF`, 其他字段与写入前一致
   - [ ] CRC 仍然通过(序列号不在校验范围内, 所以不需要重算)
   - [ ] "总线统计"里 NVM 写 = 4(与计划字节数一致)

做完这一步, 写入链路(备份→按字节写→逐字节回读→整片校验)就在真机上验证过了。

## 3. V4 写入**校验范围内**的字节(可选, 更接近真实用途)

1. 编辑器里改一个 JEDEC 时序字段(例如 tCK 或 tAA)→ **应用**。
2. 左侧对应格子应显示**红底红框**, 校验状态变 `CRC 需重算`。
3. 点 **重算 CRC** → 状态回到 `CRC 通过 · N 处改动已计入校验`。
4. 确认串 `WRITE` → 写入 → 读回确认时序与 CRC(计划里 CRC 字节应排在最后, 可在写入前预览面板的逐字节 diff 里看到)。

## 3.5 写入后的校验(三层 + 一次独立复核)

写入不是"命令没报错就算成", 程序内部有三层校验, 任一层不符就**自动回滚**:

1. **每个字节写完立即回读比对**(写一个字节 → 读一个字节);
2. 全部写完 → **整片读取**(512/1024 字节)与目标**逐字节比对**;
3. 再关掉块读/字读, 用最原始的**逐字节读法整片复核一遍** —— 防止读路径本身有系统性偏差
   让前两层"一起同意", 也能抓住分页/窗口写错位、外部工具同时动总线这类"计划之外的字节被改"。

三层都过才会报:

```
写入并校验通过: N 字节(备份 …); 校验: 每个字节写完即回读 N/N + 整片 512 字节比对 + 整片逐字节复核(关掉块读/字读, 独立读法)
```

想要**独立**再确认一次(不依赖写入流程自己): 编辑器里点
**"与设备比对(重新读取校验)"** → 程序重新整片读取设备, 与编辑器内容逐字节比较, 报"逐字节一致"
或列出不一致的偏移与两侧的值。这一下重读在 DDR5 上约 16 秒, 是"到底写进去没有"的最直接证据。

## 4. 出问题怎么办(按现象查)

| 现象 | 含义 | 处理 |
|---|---|---|
| `写入被拒绝: 变更涉及受写保护的块 [2]` | 该块 RSWP 打开, 硬件不接收写入 | 先看"查询保护状态";RSWP 只能清除(部分平台需离线模式/断电), 不可逆 |
| `写入被拒绝: 该条已处于 PSWP 永久写保护` | 永久保护(DDR2/DDR3) | SMBus 无法写入, 需高压编程器 |
| `写入中止(write)@ 0x2C5: 已写 3/4 字节, 未写 1 字节 …` | 写 NACK/超时, 中途停住 | 看同一行的回滚结果 |
| `…; 已自动回滚到写入前内容(N 字节, 读回校验通过); 备份 …` | **已恢复原状** | 无需操作;排查原因(BIOS 写保护、其他工具占用 SMBus)后重试 |
| `…; 自动回滚失败: …; 请立刻用备份 … 重新写入该条 SPD` | 硬件持续拒绝写入, 内容可能不完整 | 用该备份文件走"打开文件解析 → 写入文件… → `WRITE`";仍失败则考虑离线编程器 |
| 写入"成功"但重读内容和目标不一致 | 不可能:写入内有逐字节回读 + 整片校验 | 若真出现, 保留日志与工具版本号发我 |
| BIOS 里 SPD Write Disable 打开 | 所有写事务被 BIOS 拦截 | BIOS 关闭该项后再写 |

### 写不进去怎么办(先做"检测写入能力")

如果真实写入失败(日志里出现 `写入未完成` + 自动回滚), 先用**写保护面板里的
"检测写入能力(单字节, 写后还原)"** 把原因问清楚 —— 它会:

1. 先整片备份(内存镜像 + 文件);
2. 在一个**空闲字节**上写反值(优先选**不在 CRC 覆盖范围内**的字节, 即使探测中途断电也不会让 SPD 失效);
3. 立即回读;4. 无论结果如何都把原值写回;5. 最后整片复核与备份逐字节一致。

探测会**同时试两种写入档位**(逐字节写 → 块写), 结论里会写明哪种生效:

| 结论 | 含义 | 处理 |
|---|---|---|
| **可写**(档位 单字节 / 块写) | 写进去了 | 说明写入链路通; 若显示"块写", 说明该 hub 只认块写 —— 正式写入时程序会自动切档(日志会写"逐字节写…未生效, 已自动切换到块写") |
| **被忽略(写不进去)** | 逐字节写与块写都被接受但内容不变 | 平台或器件在拒绝: BIOS 里的 SPD Write Protect、块已被 RSWP/PSWP 保护, 或 WP# 引脚被拉低; 这不是"只能全量写"的问题(DDR5 NVM 本来就支持逐字节/块写) |
| **被拒绝** | 控制器/器件直接 NACK | 同上看具体错误文本 |

失败时日志还会打印一行**现场**:

```
现场: 0x208(页 1, cmd 0x88); MR11=0x07 MR12=0x00 MR13=0x00 MR29=0x03 MR48=0x80 MR52=0x00
```

`MR12/MR13` 是 RSWP 块位图(非 0 = 该块受保护), `MR52` bit6 = "最近有写受保护块被忽略",
`MR48` bit3 与 NVM 访问许可相关 —— 把这一行回帖就能判断是谁拒绝了写入。

### RSWP 加保护 / 清除(不可逆, 单独记)

- 两个动作**都要确认串 `CLEAR`**(在"写保护"面板的确认串框里输入;旧写法 `RSWP` 也接受)。
- 下发后程序会**回读复核**是否真的生效: DDR5 读 MR12/MR13 位图; DDR4 及更早用写测试复核。
- EE1004 的 SWP/CWP 命令需要 WP 引脚上的 VHV, 器件可能"ACK 但忽略" —— 所以"命令没报错"
  不算成功, 回读对不上会明确报错。加保护在部分颗粒上**不可逆**(清零要离线模式或断电)。

**离线恢复路径**(主板已经认不出该条时):换到能用编程器/另一台机器的环境, 把 `~/.spdrw/backups/` 里的原始镜像写回;本工具也支持"打开文件解析… → 写入文件…"对同一地址重写。

## 6. 常见问题

**Q: 写入要多久?**
每个字节一次事务 + 写周期(约 25ms), 再加回读;改 4 个字节通常在 1 秒内。改上百字节要几十秒, 期间不要切换设备/关程序。

**Q: 能不能改容量、频率这些"大字段"?**
能, 但它们属于**高危字节**(预检会单独计数并要求你确认)。写入一份与颗粒不匹配的 SPD 可能让主板拒绝该条甚至无法开机——除非你清楚后果并在牺牲条上做。

**Q: 干跑和真实写入的差别?**
干跑把写落到内存影子, 总线零写事务;真实写入在干跑同样的计划之上真正下发写事务, 并且多了"备份 → 逐字节回读 → 整片校验 → 失败自动回滚"。
